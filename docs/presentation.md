# くくシューター 演出設計

ゲームシステム（`docs/requirements.md`）の上に乗せる、見た目・アニメーション・音などの演出をまとめる。
演出を追加・変更するときは、まずこのドキュメントを更新してから実装する。

## 状態の見かた

| 状態 | 意味 |
| --- | --- |
| 採用 | やることが決まっている（未実装） |
| 実装済 | 実装した |
| 提案 | 案として出ているが、採用するか未決定 |
| 見送り | やらないと決めた |

## 基本ルール

演出はゲームを楽しくするためのもので、九九の学習とゲームの公平さを邪魔しないこと。

1. **判定を変えない**: 当たり判定・得点・敵の速さなど、ゲームのルールは演出があってもなくても同じにする
2. **問題と数字が最優先**: 敵の問題（`7 × 8`）と玉の数字は、どんな演出中でも大きく・はっきり読めるようにする。演出のエフェクトで隠さない
3. **待たせない**: 演出のせいで次の玉を投げられない時間が増えないようにする（増やすならルールとして意図して決める）
4. **強い点滅をしない**: 画面全体のフラッシュや速い点滅は避ける（光過敏への配慮）
5. **色だけに頼らない**: 正解・ハズレなどの区別は、色に加えて形・動き・文字でも分かるようにする
6. **調整できるようにする**: アニメーションの時間・大きさなどの数値は 1 か所にまとめ、後から調整できるようにする

## 全体の雰囲気

- 女の子向けのファンシーな色使い（ユーザー指定）
- パステルカラー中心。ふわふわ・きらきら・まるい形
- 敵は怖くしない。「やっつける」というより「いたずらっ子をおとなしくさせる」くらいの、やさしい雰囲気

### 色（たたき台）

| 用途 | 色 | メモ |
| --- | --- | --- |
| 背景 | `#fde7f3` → `#e8dcff`（ピンク→ラベンダーのグラデーション） | |
| 文字（基本） | `#5a3a6e`（濃いむらさき） | 明るい背景の上でも読めるよう、文字は濃い色にする |
| 敵 | `#b8e6d8`（ミント）、`#d9c8ff`（ライラック）、`#ffd6e0`（ピーチ）など | |
| 玉 | `#fff3b0`（クリーム）＋つやのハイライト | |
| アクセント | `#ff8fb8`（ピンク）、`#ffd166`（きいろ） | ボタン・得点など |
| 防衛ライン | `#ff8fb8` の点線 | 危ないときは濃くする |

色は実装時に実際の画面で見ながら調整する。

### キャラクター（決定）

オリジナルのキャラクターにする（既存の作品のキャラクターには似せない）。

| 対象 | 決定 | デザインのポイント |
| --- | --- | --- |
| 自分 | うさぎ耳の女の子 | ピンクのうさぎ耳フード、にっこり目、ほっぺにピンク、胸元にリボン、パステルのワンピース。投げるときは両手で玉を頭の上に持ち上げて、えいっと前へ（U3） |
| 敵 | もこもこ雲のいたずらっ子 | もこもこの雲にいたずら顔。体の色はミント／ライラック／ピーチ。問題（`7 × 8`）はおなかに大きく書く。倒すと雲が晴れてお花が弾ける（U4・P4） |
| 玉 | キャンディ | 両端に包み紙のついた丸いキャンディ。色はピンク／こむぎいろ／ミント。つやのハイライトを付ける。数字が読みにくくならないよう、中央は無地にして数字を濃く書く |

- 敵の問題と玉の数字の読みやすさを最優先する（基本ルール 2）
- 絵は、まず Canvas の図形の組み合わせで描く（画像ファイルなしで作れて、色や大きさを調整しやすい）。もっと描き込みたくなったら画像に差し替える
- 自分・玉・敵を好きな画像に差し替えるための画像の仕様は `docs/custom-images.md`（仕様のみ決定、未実装）

## 実装メモ

- 色・フォントは `src/render/theme.ts`、キャラクターの絵は `src/render/sprites.ts`
- 上のバーは不透明にする（半透明だと、下に入りかけた敵の問題が透けて読めてしまい紛らわしい）
- キャンディの色は数字から決める（九九の答えを小さい順に並べて 3 色を順番に割り当てる）。同じ玉は飛んでいる間も同じ色のまま。色に意味はない
- 敵（もこもこ雲）の色は敵の番号で順番に決める
- もこもこ雲は当たり判定の矩形より上に約 11px はみ出して描く（判定は変えない）
- もこもこ雲には白いふちを付ける（よる の背景はライラック色の雲と近い色なので、ふちがないと雲が背景に溶けてしまう）

- 演出用の数値（時間・大きさ・色）は、ゲームの調整値（`src/config.ts`）とは別にまとめる予定（例: `src/render/theme.ts`）
- U1: 見た目の位置は `src/render/ballView.ts`。転がる速さ 420 px/秒。止まる位置までの距離ぶん回すので、止まるとちょうど数字がまっすぐになる。転がっている途中の玉も、見えている位置で押せる
- U2: 2 次ベジェ曲線。曲がる向きは投げるたびにランダム、曲がり具合は `BALL.curve`
- U3: 「ため」0.15 秒（`BALL.windup`）の間に、玉がスロットから頭の上の手へぴょんと移り、手に持つ大きさ（0.6 倍）まで小さくなる。その後「えいっ」のポーズで投げ、玉は元の大きさに戻りながら回って飛ぶ
- P8: 押した玉は持ち上げる瞬間に「ぷにっ」とへこむ。玉が飛んでいる間に押した玉はぷるぷる揺れる
- 段階 3 の演出は `src/render/effects.ts`（時間・数などの調整値は `EFFECT`）。ゲームの判定・得点には関わらない
- U4・P4: 倒した雲は 0.3 秒でふくらみながら透明になり、お花（基本 7 個）が勢いよく弾けて、式の文字の外側まで広がる。玉は黄色いきらきらになって消える
- P1・P2: 命中した場所に式（`7 × 8 = 56`）と、その下にほめことばを 1.2 秒出す。防衛ラインから 6 割より高い位置で倒すと特別なほめことば（かんぺき！ など）。式とほめことばは、倒した敵のレーンの幅に収まるよう文字を縮める（隣のレーンの敵と重なると、どちらかの文字が読めなくなるため）
- P1〜P4 の文字とお花は、**敵より下の層**に描く（ほかの敵の問題を隠さないため。基本ルール 2）
- P3: ハズレなしで 3 回以上続けて当てると、防衛ラインの少し上に「N れんぞく！」。れんぞく 1 回ごとにお花が 2 個増える（上限 17 個）。れんぞくはステージをまたいで続き、ハズレか新しいゲームで 0 に戻る
- P6: ハズレの玉が雲と重なった瞬間、その雲が横に伸び縮みし、玉も大きさが揺れる（同じ玉・同じ雲で 1 回だけ）
- U5: 得点の数字（`+230`）が上のバーの得点へ 0.6 秒で飛び、着いたら得点が数え上がってぴょこっと大きくなる。ステージクリア画面などでは本当の得点（クリアボーナス込み）を出す
- 段階 4 の動きは `src/render/motion.ts`（調整値は `MOTION`）。どれも見た目だけで、当たり判定の位置は動かさない
- P9: 敵は左右に ±4px、上下に ±1.5px ゆらゆら揺れる（敵ごとにタイミングをずらす）。上のバーは不透明で敵はその下から出てくるので、バーの下から出てくる間は 0.8 倍からふくらんで通常の大きさになる
- P5: 防衛ラインまで 110px 以内に来た敵は、近いほど強くぷるぷる震える（最大 ±1.6px）。防衛ラインは、いちばん近い敵に合わせて濃く太くなり、半分より近いと濃いピンクになって、ゆっくり脈打つ（強い点滅はしない）
- P10: 自分は足元を軸にゆらゆら揺れ、耳は少し遅れて大きめに揺れる。3.2 秒ごとに 0.13 秒まばたきする。投げている間は揺れない。タイトル画面の女の子も同じように動く
- 動きの時計（`Effects.time`）はポーズ中は止まる
- P12: 背景は `src/render/theme.ts` の `STAGE_BACKGROUNDS`。あさ → ひる → ゆうがた → よる（星がまたたく）の順に変わり、5 ステージ目からまた あさ に戻る。文字が読めるよう、どれも明るめのパステル。タイトル・設定画面は あさ
- P11: ステージクリア画面で花びらが降り、星が 1 つずつ出る。星はそのステージのハズレの回数で決める（0 回 ★3「パーフェクト！」、1〜3 回 ★2「よくできました！」、4 回以上 ★1「クリア！」。`EFFECT.stars3MaxMisses`・`stars2MaxMisses`）。ハズレの回数も表示する。星は得点に関係しない
- P14: タイトル ⇄ せってい、タイトル → プレイ、ステージクリア → 次のステージ、ゲームオーバー → タイトルは、背景色のレイヤーが 0.35 秒で薄くなって新しい画面がふわっと出る。ステージクリア・ゲームオーバーは、プレイ画面の上にレイヤーが 0.4 秒で濃くなる。ポーズの出入りはすぐ切り替える（`src/render/renderer.ts`）
- U1 は玉の並び順そのものが変わるので、ゲームロジック側も変える: 投げた玉をストックから抜いて残りを左に詰め、補充する玉は常に右端に入れる
- ゲームロジック（`src/game/`）は演出を知らなくてよいようにする。演出に必要なきっかけ（投げた・当たった・ハズレた など）は `GameEvents` で受け取る

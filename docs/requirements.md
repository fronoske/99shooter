# 九九シューティング 要件定義

## 概要

- 小学2年生向けに九九を学べる、スマートフォンのブラウザで動くゲーム
- 現段階ではゲームシステムの構築を優先する。キャラクターデザイン・演出は最低限とし、後で強化する

## 技術構成

- TypeScript + Vite、Canvas 2D 描画
- ソース: `src/`、ビルド成果物: `dist/`、テスト: `test/`（Vitest）
- 縦画面。論理解像度 360×640 を画面に合わせて拡大縮小する（アスペクト比維持）

## ゲームシステム

### 画面構成

- 画面下部に自分（プレイヤー）と防衛ライン
- 自分の下に「玉」が横一列に並ぶ（初期値 5 個、設定変更可）
- 敵は画面上部から出現し、下へ降りてくる

### 敵

- 各敵は九九の問題（例: `2 × 4`、`8 × 9`）を持つ
- 出現位置は横方向のレーン単位で、直前の敵と重ならないようにする
- 同じ問題の敵が同時に画面に出ることはない
- 敵が防衛ラインに到達したらゲームオーバー

### 玉

- 各玉には数字（九九の答えに当たる数）が書いてある
- プレイヤーが玉をタップすると、その玉が飛んでいく
  - 画面上に答えが一致する敵がいる場合: その敵めがけて飛び、命中すると玉も敵も消える
    - 一致する敵が複数いる場合は、最も防衛ラインに近い（最も下にいる）敵を狙う
  - 一致する敵がいない場合: 玉は上に飛び、敵を素通りして画面外に消える
- 玉は、投げるまでに「ため」（0.15 秒）がある。この間に自分が玉を頭の上に持ち上げ、そこから飛んでいく
- 玉は少し曲がって飛ぶ（曲がる向きは毎回ランダム）。答えが一致する敵がいれば、動いている敵を追いかけて当たる
- 玉が飛んでいる間は次の玉を投げられない
- 投げた玉はストックから抜け、残りの玉は左に詰まる。玉が敵に命中する、または画面外に消えたら、右端に新しい玉が補充される
- 玉には「ハズレ」（画面上のどの敵の答えにも一致しない数）を混ぜる
  - ハズレは、画面上の問題の近い答え（同じ段の前後など）や他の九九の答えから選び、当てずっぽうで当たりにくくする
- ストックの玉のうち、画面上の敵の答えに一致する玉が必ず 1 つ以上あるようにする（画面に敵がいて、玉が飛んでいない場合）
- 一番下（防衛ラインに最も近い）の敵の答えの玉は、必ずストックにあるようにする（玉が飛んでいない場合）
  - 九九が分かっていれば、一番下の敵はいつでも倒せるようにするため（確率しだいで正解が来ずにゲームオーバーになる不公平を防ぐ）
  - 補充時に、一番下の敵の答えがストックになければ、補充する玉をその答えにする
  - 敵はすべて同じ速さで降りるため順番が入れ替わらず、補充時の処理だけでこの約束が保たれる。敵ごとに速さを変える場合は見直しが必要
  - ほかの敵の答えは確率で混ざる
- ストックにもとからある玉の数字は途中で変えない。数字が決まるのは、投げた玉のスロットを補充するときだけ
  - 補充した結果、正解の玉が 1 つもなければ、補充した玉を正解にする
- 補充されたばかりの玉（右端）だけが正解になりやすい、という偏りを作らない（偏りがあると、九九を考えずに右端を投げるだけで進めてしまう）
  - 新しい敵の問題は、一定の確率（`SPAWN.matchHeldProbability`、初期値 0.7）で、手持ちのハズレの玉の数字が答えになるものを選ぶ。もとからある玉があとから正解に変わるので、補充の玉を正解にする必要が減る
  - 前もって決めた問題の答えの玉が、出す時点で手持ちになければ、その時点の手持ちに合わせて選び直す
  - 確認方法（テストで自動確認）: 2 秒おきに 8 割は一番下の敵の正解、2 割はハズレを投げる想定で、当てた直後の右端の玉とほかの玉の正解の割合の差が 12 ポイント未満。直す前は 右端 約 85% / ほかの玉 約 10%、直した後は どちらも約 23%（玉全体の正解の割合は直す前とほぼ同じ）
- 次に出す敵の問題は前もって決めておく
  - 画面に敵が 0 匹のときは、次に出す敵の答えを正解とみなして玉を補充する。これにより、敵が出てきた時点でその敵の正解玉がすでにある
- ストック内で同じ数字の玉は重複させない

### ステージ

- 1 ステージで規定数（初期値 20 匹）の敵を倒すとクリア
- クリア時はステージクリア画面を表示し、タップで次のステージへ
- ステージが進むほど、敵の落下速度・出現間隔・同時出現数が厳しくなる
- 各ステージで出題する段（1〜9 の段）は設定で指定可能

### スコア

- 敵を倒すと得点。高い位置（防衛ラインから遠い位置）で倒すほど高得点
- ステージが進むほど得点倍率が上がる
- コンボボーナス: ハズレなしで続けて当てると得点倍率が上がる（1 回目 ×1.0、1 回ごとに +0.1、上限 ×2.0）。ハズレで ×1.0 に戻る。ステージをまたいで続き、新しいゲームで 0 に戻る
  - ねらい: 当てずっぽうで投げると損をするので、九九を考えて投げる理由になる
  - 2 回以上続いている間は、上のバーに今の倍率（×1.3 など）を出す。3 回以上の「れんぞく！」の表示にも倍率を出す
  - クリアボーナスにはかけない
- ステージクリア時にクリアボーナス
- 計算式のパラメータは `src/config.ts` で調整可能にする

### 画面遷移

- タイトル → プレイ → ステージクリア → プレイ（次ステージ） … → ゲームオーバー → タイトル
- タイトル ⇄ せってい
- プレイ ⇄ ポーズ。ポーズから「やめる」でタイトルへ（その回の得点は記録しない）

### ポーズ

- プレイ画面の上のバー（ステージ・得点の帯）全体をタップするとポーズ。ボタンの絵は出さず、バーの右端に小さな目印だけ出す
  - 雲や玉を押したときはポーズしない（小学 2 年生は狙った雲を直接タップしがちなため、画面の広い範囲をポーズにしない）
  - 画面下の玉から離して、玉の連打中に押し間違えないようにする
- ポーズ中は敵も玉も止まる
- ポーズ画面には「つづける」（大きく目立つ）と「やめる」（小さく地味）を置く
  - 「やめる」をプレイ画面に直接置かず、ポーズ画面の中に入れて 2 段階にし、誤操作を防ぐ
- ポーズ中は、プレイ画面の上に半透明のレイヤーを重ね、プレイ画面がうっすら見えるようにする（濃さは `src/render/renderer.ts` の `pauseOverlay`）
- ほかのアプリへの切り替え・画面の消灯などでページが見えなくなったら、自動でポーズする
- タイトルには「スタート」「せってい」ボタンと、現在のむずかしさを表示する

### せってい画面

- 設定は端末のブラウザ（localStorage）に保存し、次回も引き継ぐ。保存できない・壊れている場合は既定値を使う
- むずかしさ: やさしい（既定）/ ふつう / むずかしい
  - 敵の落下速度・出現間隔・最大同時出現数・正解玉の出やすさ・得点倍率を変える（値は `src/config.ts` の `DIFFICULTY`）
  - むずかしいほど高得点
  - ゲーム開始時の設定がそのゲームの終わりまで使われる
- こうかおん: 音量を 6 段階（オフ・1〜5、既定 3）で選ぶ
  - 端末によって聞こえる音量が違うため、オン・オフではなく段階で調整できるようにする
  - 1 段で約 4.5dB ずつ変わる。大きくしても音が割れないよう、最後にリミッターを通す
  - 選んだ直後に命中の音を鳴らして、大きさを確かめられるようにする
  - 以前のオン・オフの保存データは、オン = 3・オフ = 0 として引き継ぐ
  - 効果音は Web Audio API で合成する（音声ファイルなし）。曲と同じ調で、命中の音はそのときの BGM の和音に合った高さで鳴り、れんぞくが続くほど高くなる。ハズレは「ぽよん」とはずむ音で、そのとき BGM を少し小さくする。ほかに タップ・投げる・ステージ開始・れんぞくの節目（3・5・10…回）・ステージクリア・ゲームオーバー
  - iOS などの制約のため、最初のタップで音を有効にする
- BGM: 音量を 6 段階（オフ・1〜5、既定 3）で選ぶ。設定画面ではタイトルの曲が流れているので、選んだ大きさをそのまま確かめられる
  - BGM も Web Audio API で合成する（音声ファイル・ライブラリなし）。タイトル画面は静かな版、プレイ中はステージで倒した数に合わせて楽器が増える（和音とベース → 4 分の 1 でドラム → 半分でメロディ → 4 分の 3 で手拍子ときらきら）。ステージが進むとテンポが上がる（112 → 最大 136 BPM）。ポーズ中は止まり、続きから再開する。ステージクリア・ゲームオーバーで止まる。スタート・次のステージのときは、曲を一瞬（0.7 秒）止めてスタートの合図を鳴らしてから始める
- バイブレーション: オン（既定）/ オフ
  - 命中・ゲームオーバーで振動。Vibration API 対応端末（Android の Chrome など）のみ
  - 非対応端末（iPhone の Safari など）ではボタンを押せなくし、その旨を表示する
  - オンにしたときに 1 回振動して確認できる
- 「もどる」でタイトルへ

## 調整可能パラメータ（`src/config.ts`）

- 難易度ごとの補正（`DIFFICULTY`）
- 玉の数、正解玉の出現確率
- 1 ステージの撃破目標数
- ステージごとの敵速度・出現間隔・最大同時出現数・出題する段
- スコア（基本点、高さボーナス、ステージ倍率、クリアボーナス）
